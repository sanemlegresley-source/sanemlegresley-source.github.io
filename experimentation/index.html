Project 05

Online controlled experiments

Working notes and a small toolkit on A/B testing — the method a team reaches for when it wants to know whether a change actually helped, rather than argue about it. This page collects the parts I find myself explaining most: how to size a test, how to read a result without fooling yourself, and the traps that quietly invalidate one.

Why bother with a controlled experiment?

Ship a change and watch the metric move, and you can never fully separate the change from everything else that moved that week — a campaign, a season, a press mention. Randomly assigning users to a control and a treatment group holds all of that constant on average, so a difference between the groups is attributable to the change itself. That's the whole reason experiments earn trust: they estimate a causal effect, not a correlation.

The discipline is less about running the test and more about the decisions around it — picking a metric that reflects real value, sizing the test so it can actually detect a meaningful effect, agreeing on the call before the data arrives, and knowing which results not to trust. The tools below are for those decisions.

Anatomy of a trustworthy test

Design

One clear hypothesis, a randomisation unit (usually the user), a single primary metric, and a short list of guardrails — metrics that must not get worse (latency, unsubscribes, refunds). Decide the success rule before launch.

Power

Fix the smallest effect worth acting on — the minimum detectable effect — then size the test so it has a real chance (usually 80%) of catching an effect that big. Underpowered tests waste time and mislead.

Readout

Report the effect with a confidence interval, not just a p-value and an arrow. Check the guardrails and a couple of key segments, then make the pre-agreed call. "Flat" is a legitimate, useful outcome.

Traps worth knowing

Peeking. Stopping the moment a result crosses significance inflates false positives badly. Either fix the sample size in advance, or use a sequential method built for continuous monitoring.

Multiple comparisons. Test twenty metrics at 95% and roughly one will look "significant" by chance. Pre-register a primary metric; correct the rest.

Novelty & primacy. Regulars react to any change at first. An effect that fades over the test — or only appears late — needs a longer look before you believe it.

Interference (SUTVA). In marketplaces and social products, treating one user can spill over to a control user, biasing the estimate. Cluster or switchback designs help.

Simpson's paradox. A pooled result can reverse inside every segment if the mix shifted. Always check the primary metric by key segment.

Variance reduction (CUPED). Using pre-experiment data to remove predictable variance can cut the sample size needed for the same power — often substantially, for free.
